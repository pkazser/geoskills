# 7. GeoPython QA — μπορώ να εμπιστευτώ το αποτέλεσμα;

## Τι θα μάθεις

Θα μετατρέψεις τους ελέγχους σε σαφές checklist και θα εντοπίσεις λογικά λάθη που μπορεί να περάσουν από τον κώδικα.

## QA matrix

| Έλεγχος | Τι περιμένουμε |
|---|---|
| CRS | όλα τα analytical layers στο `EPSG:2100` |
| Rows/features | 7 cleaned services, 3 essential buffers, 3 zones |
| Geometry | points/lines/polygons όπως ορίζει το layer |
| Validity | no null, empty ή invalid geometry |
| Bounds | services και buffers μέσα ή κοντά στη study area |
| Attributes | μοναδικά service ids, no missing zone id |
| Measurements | θετικά areas, coverage ≤ zone area |
| Visual | σημεία, ζώνες, roads και buffers ευθυγραμμίζονται |

## Παράδειγμα assertions

```python
assert cleaned.service_id.is_unique
assert cleaned.geometry.notna().all()
assert cleaned.geometry.is_valid.all()
assert services_with_zones["zone_id"].notna().all()
assert (coverage_by_zone["covered_m2"] > 0).all()
assert (coverage_by_zone["covered_m2"] <= coverage_by_zone["zone_area_m2"]).all()
```

Οι assertions δεν αντικαθιστούν την κατανόηση. Ένας έλεγχος μπορεί να περνά επειδή συγκρίνεις λάθος columns ή επειδή όλα τα features έχουν λάθος CRS.

## Εφαρμογή και αναμενόμενο αποτέλεσμα

Τρέξε τους ελέγχους μετά από κάθε στάδιο και κράτησε counts πριν/μετά. Αν αποτύχει ένας έλεγχος, μην κάνεις export για να “δεις αν ανοίγει”. Εξήγησε τη ρίζα: path, type, CRS, predicate, geometry ή business rule.

## Checkpoint

Γράψε έναν έλεγχο που δεν είναι απλή `assert`, αλλά λογικός έλεγχος: “καμία υπηρεσία δεν πρέπει να έχει zone_id εκτός των γνωστών ζωνών”. Πρόσθεσε και έναν visual check με legend.

## Επόμενο lesson

Μόνο μετά το QA οργανώνεις τα τελικά layers και τα deliverables.
