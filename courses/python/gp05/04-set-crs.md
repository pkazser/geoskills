# 4. `set_crs`: δήλωση, όχι μετασχηματισμός

## Τι θα μάθεις

Θα ξεχωρίζεις τη δήλωση του CRS από την αλλαγή θέσης.

## Γιατί είναι χρήσιμο

CSV αρχεία συχνά έχουν longitude/latitude αλλά κανένα metadata. Πρέπει να δηλώσεις τι σημαίνουν οι αριθμοί πριν ζητήσεις μετασχηματισμό.

## Παράδειγμα

```python
gdf = gpd.GeoDataFrame(df, geometry=points)
gdf = gdf.set_crs("EPSG:4326")
```

Το `set_crs` προσθέτει πληροφορία στο GeoDataFrame. Οι αριθμοί των σημείων δεν αλλάζουν.

## Νοητικό μοντέλο

Input είναι geometry χωρίς σωστό metadata και output η ίδια geometry με δηλωμένο CRS. Το `set_crs` δεν αλλάζει numeric coordinates και δεν μετατρέπει μοίρες σε μέτρα.

## Συνηθισμένο λάθος

Μην χρησιμοποιήσεις `set_crs("EPSG:2100")` επειδή θέλεις μέτρα ενώ οι τιμές είναι longitude/latitude. Θα πεις ψέματα στο GeoDataFrame. Το αποτέλεσμα μπορεί να φαίνεται έγκυρο τεχνικά αλλά να βρίσκεται σε λάθος θέση.

## QA και άσκηση

Κράτησε ένα αντίγραφο των geometry πριν και μετά το `set_crs` και έλεγξε ότι είναι ίδιες. Έλεγξε επίσης bounds: περίπου 21–26 και 35–41 σημαίνουν μοίρες Ελλάδας, όχι μέτρα.

### Σωστό και λάθος παράδειγμα

Αν οι raw columns είναι longitude/latitude, πρώτα δημιουργείς geometry και κάνεις `set_crs("EPSG:4326")`. Μετά κάνεις `to_crs("EPSG:2100")`. Το λάθος `set_crs("EPSG:2100", allow_override=True)` δεν μετακινεί τα σημεία· απλώς βαφτίζει degrees ως metres. Έτσι καταστρέφεται η χωρική ερμηνεία και κάθε μέτρηση που ακολουθεί είναι αναξιόπιστη.

Το `set_crs` είναι δήλωση: “αυτοί οι αριθμοί ήδη ανήκουν εδώ”. Δεν είναι εργαλείο μετατροπής.

## Επόμενο βήμα

Τώρα που δήλωσες σωστά το αρχικό CRS, θα κάνεις πραγματικό μετασχηματισμό με `to_crs`.
