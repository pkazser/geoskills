## Τι θα μάθεις

Θα ελέγξεις το dataset πριν από οποιοδήποτε export.

## Τι αποδεικνύει το QA

Τα rows δείχνουν αν χάθηκαν records, το schema και οι types αν οι στήλες είναι χρησιμοποιήσιμες, το CRS αν οι coordinates ερμηνεύονται σωστά και η geometry αν κάθε asset έχει θέση. Τα bounds και ο χάρτης ελέγχουν τη γεωγραφική λογική.

```python
assert len(gdf) == len(df)
assert len(gdf) > 0
assert gdf.crs is not None
assert gdf.geometry.geom_type.eq("Point").all()
assert gdf.geometry.notna().all()
assert gdf.drop(columns="geometry").isna().sum().sum() == 0
assert gdf.geometry.is_empty.sum() == 0
assert gdf.geometry.is_valid.all()
assert gdf["asset_id"].is_unique
assert gdf["longitude"].between(-180, 180).all()
assert gdf["latitude"].between(-90, 90).all()
```

## Bounds και χάρτης

```python
print(gdf.total_bounds)
gdf.plot(figsize=(7, 6), color="navy")
```

Τα bounds και ο χάρτης λειτουργούν ως αριθμητικός και οπτικός έλεγχος.

## Γιατί είναι χρήσιμο

Το QA πριν από export είναι το σημείο όπου σταματάμε ένα λανθασμένο workflow. Οι έλεγχοι καλύπτουν όχι μόνο τη geometry αλλά και τη σύνδεσή της με τα attributes.

## Τι πρέπει να παρατηρήσεις

Το `total_bounds` επιστρέφει `[minx, miny, maxx, maxy]`. Ο χάρτης πρέπει να δείχνει ένα συνεκτικό σύνολο σημείων στην περιοχή του dataset, όχι σημεία σε μη αναμενόμενες θέσεις.

## Πρόσεξε

Το `is_valid` μπορεί να είναι `True` ακόμη και όταν οι συντεταγμένες έχουν τοποθετηθεί σε λάθος χώρα. Χρειάζεσαι και λογικό/οπτικό έλεγχο.

## Τι αποδεικνύει κάθε check;

Το feature count δείχνει αν χάθηκαν ή προστέθηκαν rows. Το CRS δείχνει ποια ερμηνεία δηλώνεται για τις coordinates. Ο geometry type και το `notna()/is_empty` ελέγχουν δομή και πληρότητα. Τα bounds δείχνουν τάξη μεγέθους και περιοχή. Ο χάρτης συνδυάζει αυτά τα στοιχεία οπτικά και μπορεί να αποκαλύψει outlier που δεν φαίνεται σε έναν πίνακα.
