# GeoSkills — Codex Project Instructions

## Mandatory course development standards

Before creating, editing, reviewing, or publishing GeoSkills
educational content, read and follow:

1. docs/standards/GEOSKILLS_COURSE_DEVELOPMENT_STANDARD_v1.1.md
2. docs/standards/GEOSKILLS_COURSE_QA_CHECKLIST_v1.1.md
3. docs/standards/GEOSKILLS_COURSE_TEMPLATE_v1.1.md

Adapt the template to the educational subject. Do not impose
the same structure on Python, QGIS, AI Learning and Field Surveying.

## Educational quality

- Preserve approved educational content.
- Use natural Greek and consistent scientific terminology.
- Prioritize practical skills and educational clarity.
- Use responsive MyST figures and properly licensed images.
- Maintain clear learning objectives, activities and assessment.

## Workflow and safety

- Inspect git status before making changes.
- Protect existing work and unrelated courses.
- Use isolated worktrees when appropriate.
- Never commit, push, merge or deploy without explicit approval.
- Follow the documented QA and release gates.
- Record browser and release checks explicitly as PASS, FAIL, NOT TESTED,
  or CONDITIONAL GO. NOT TESTED is never PASS; CONDITIONAL GO requires
  explicit owner approval, scope, rationale, and a re-test date.
- Do not change production workflows, shared CSS, theme or dependencies
  without explicit approval.

## Authority

The course instructor approves educational content and releases.
If instructions conflict, report the conflict before proceeding.
