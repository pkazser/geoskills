# GeoSkills — Educational Notebook Standard v1.0

**Κατάσταση:** εγκεκριμένο εκπαιδευτικό πρότυπο (πιλοτική εφαρμογή GP00.5).

**Πεδίο:** φοιτητικά starter notebooks (`.ipynb`) του GeoPython Core και, με κατάλληλη προσαρμογή, άλλων μαθημάτων GeoSkills.

**Σχέση με τα υπάρχοντα πρότυπα:** συμπληρώνει, δεν αντικαθιστά, τα `GEOSKILLS_COURSE_DEVELOPMENT_STANDARD_v1.1.md`, `GEOSKILLS_COURSE_QA_CHECKLIST_v1.1.md` και `GEOSKILLS_COURSE_TEMPLATE_v1.1.md`.

## 1. Παιδαγωγικός σκοπός

Το notebook είναι **εκπαιδευτική διαδρομή** και όχι απλώς συλλογή εκτελέσιμων εντολών. Ο φοιτητής πρέπει να μπορεί να εξηγήσει **τι κάνει ο κώδικας, γιατί το κάνει, τι περιμένει να συμβεί και πώς ελέγχει το αποτέλεσμα**. Οι οδηγίες είναι κατανοητές από αρχάριους· δεν προϋποθέτουν γνώσεις που δεν παρουσιάστηκαν ακόμη.

Συνολική αρχή: **Εξηγώ → Εκτελώ → Παρατηρώ → Επαληθεύω → Ερμηνεύω**.

## 2. Ελάχιστη δομή

1. **Εισαγωγικό κελί Markdown:** στόχος, είσοδοι, αναμενόμενο παραδοτέο, προαπαιτούμενα (με παραπομπή στην αντίστοιχη ενότητα όπου είναι απαραίτητο).
2. **Κελί προετοιμασίας:** προηγείται κατανοητή περιγραφή της δουλειάς του (εύρεση/λήψη/έλεγχος δεδομένων), τι εκτελεί ο φοιτητής και ποιο μήνυμα σημαίνει επιτυχία. Το σύνθετο υποστηρικτικό implementation δεν απαιτεί επεξήγηση γραμμή προς γραμμή.
3. **Βήματα δραστηριότητας:** για κάθε σημαντικό νέο βήμα υπάρχει σύντομο Markdown *πριν* από τον κώδικα. Ακολουθεί περιορισμένος κώδικας και ένα σαφές ερώτημα παρατήρησης ή checkpoint *μετά*, όπου προσφέρει μαθησιακή αξία.
4. **Mini Challenge:** ζητούμενο, συγκεκριμένα παραδοτέα, περιορισμοί, ελάχιστοι έλεγχοι επιτυχίας. Οι βασικές αποφάσεις/λύσεις παραμένουν στον φοιτητή.
5. **Τελικός αυτοέλεγχος:** ο φοιτητής μπορεί να περιγράψει το αποτέλεσμα, να εξηγήσει κρίσιμες παραμέτρους και να αναφέρει περιορισμούς του ελέγχου.

**Δεν είναι υποχρεωτικό** ένα Markdown κελί πριν και μετά από *κάθε* μικρό code cell. Σπάμε τα βήματα σύμφωνα με τις μαθησιακές έννοιες, όχι με αυθαίρετο αριθμό κελιών.

## 3. Σχόλια μέσα στον κώδικα

- Σχόλιο **στην πρώτη ουσιαστική χρήση** νέας συνάρτησης, σύνταξης ή μη προφανούς παραμέτρου.
- Ειδική επεξήγηση σε αποφάσεις χωρικής σημασίας: `crs`, `geometry`, σειρά X/Y, `layer`, `predicate`, `distance`, μονάδες, `to_crs()` έναντι `set_crs()`.
- Τα σχόλια εξηγούν **πρόθεση ή κίνδυνο**, όχι προφανή σύνταξη (`# εκτυπώνουμε` πάνω από κάθε `print`).
- Ονόματα μεταβλητών και κειμένου παραμένουν συνεπή μεταξύ μαθήματος και notebook.
- Χρησιμοποιούμε φυσικά ελληνικά. Οι κώδικες, μεταβλητές και ονόματα βιβλιοθηκών παραμένουν στην ακριβή μορφή της Python.
- Δεν γεμίζουμε τα κελιά με μεγάλα κείμενα· αυτά ανήκουν σε Markdown.
- Ένα TODO δίνει **στόχο/υπόδειξη**, όχι τον έτοιμο κώδικα της λύσης.

### Παράδειγμα κατάλληλου διαχωρισμού

**Πριν (Markdown):** «Θα διαβάσουμε το CSV ως πίνακα. Στη συνέχεια ελέγχουμε πόσες εγγραφές διαβάστηκαν και ποιες στήλες περιέχει».

```python
import pandas as pd  # pandas: εργαλεία για πίνακες δεδομένων

df = pd.read_csv(data_path)  # data_path: διαδρομή του εκπαιδευτικού CSV
print(df.shape)
print(df.columns.tolist())
```

**Μετά (Markdown):** «Πόσες γραμμές εμφανίζονται; Υπάρχουν οι στήλες που χρειαζόμαστε; Το `shape` δεν αποδεικνύει από μόνο του ότι οι τιμές είναι σωστές».

Αν το `pd` έχει ήδη εξηγηθεί στο GP00.5, σε μεταγενέστερο notebook δεν επαναλαμβάνουμε τη βασική εξήγηση· εξηγούμε μόνο τη νέα χρήση.

## 4. `import`, `from` και βιβλιοθήκες

Κατά την εισαγωγή νέας βιβλιοθήκης, ο φοιτητής πρέπει να διακρίνει:

| Σύνταξη | Νόημα |
|---|---|
| `import math` | χρησιμοποιούμε το module μέσω του ονόματος `math`, π.χ. `math.sqrt(25)` |
| `import pandas as pd` | ίδιο module, με σύντομο όνομα/alias `pd` |
| `from shapely.geometry import Point` | εισάγουμε απευθείας το συγκεκριμένο αντικείμενο `Point` |
| `python -m pip install ...` | εγκατάσταση πακέτου στο επιλεγμένο περιβάλλον — **δεν** ισοδυναμεί με `import` |

Στην πρώτη εισαγωγή δίνουμε επίσης μία φράση για **τι προσφέρει** η βιβλιοθήκη και πότε χρειάζεται. Δεν απαιτείται αποστήθιση εγκαταστάσεων στην αρχή του GP00.

## 5. Κελιά υποστηρικτικής προετοιμασίας

Τα αυτοματοποιημένα setup cells (π.χ. `DATA_ROOT`, λήψη CSV/GeoPackage, έλεγχοι cache) σημειώνονται ως **«Εκτέλεσε πρώτα — μη μεταβάλεις»**. Ένα Markdown κελί εξηγεί:

- ποια αρχεία προετοιμάζουν και πού,
- τι ελέγχεται πριν συνεχίσει η άσκηση,
- ποιο success/error message να προσέξει ο φοιτητής,
- ότι πρόκειται για βοηθητικό μηχανισμό, όχι για την κύρια άσκηση.

Δεν αναδιοργανώνουμε, αφαιρούμε ή απλουστεύουμε λειτουργικό setup cell απλώς για περισσότερα σχόλια. Διατηρούμε τη δοκιμασμένη συμπεριφορά τοπικά και στο Colab.

## 6. Ασκήσεις και checkpoints

- **Guided example:** μία σύντομη λυμένη επίδειξη όταν εισάγεται νέα έννοια.
- **Student TODO:** ουσιαστική εργασία που απαιτεί απόφαση/σύνταξη από τον φοιτητή, χωρίς έτοιμη απάντηση στον ίδιο κώδικα.
- **Expected observation:** περιγράφουμε την τάξη μεγέθους ή το είδος του αποτελέσματος· ποτέ επινοημένα ακριβή outputs.
- **GeoPython QA:** έλεγχοι όπως rows, IDs, schema, CRS, geometry, bounds, missing/invalid, export/read-back κατά περίπτωση. Καταγράφουμε **τι αποδεικνύει** και **τι δεν αποδεικνύει** κάθε έλεγχος.
- Οι λύσεις και πλήρη reference scaffolds παραμένουν εκτός δημόσιου student notebook.

## 7. Προοδευτική υποστήριξη

- **GP00:** περισσότερες σύντομες εξηγήσεις για σύνταξη, βιβλιοθήκες, εισόδους/εξόδους.
- **GP01–GP05:** εξηγούμε τη νέα GIS πράξη και αναφέρουμε στοχευμένα παλαιότερες έννοιες, χωρίς επανάληψη όλης της θεωρίας.
- **GP06–GP10 / Capstone:** περισσότερες αποφάσεις και QA από τον φοιτητή, λιγότερα σχόλια σε ήδη διδαγμένη σύνταξη.

Το επίπεδο καθοδήγησης προσαρμόζεται στον στόχο και δεν καθορίζεται από σταθερό πλήθος σχολίων ή κελιών.

## 8. Τεχνικές απαιτήσεις starter notebooks

- Έγκυρο JSON/nbformat, kernel metadata συμβατό με Python 3.
- Καμία αποθηκευμένη έξοδος (`outputs: []`) και κανένα execution count (`execution_count: null`) στα παραδιδόμενα starter notebooks.
- Καμία δημοσίευση έτοιμων λύσεων, tokens, τοπικών προσωπικών διαδρομών ή μυστικών.
- Καμία ανεξέλεγκτη αλλαγή datasets, URLs, εξαρτήσεων ή setup code.
- Τα μη συμπληρωμένα TODOs μπορούν σκόπιμα να εμποδίζουν το `Run all`: αυτό **δεν** είναι αποτυχία runtime. Πλήρης λειτουργική δοκιμή με ιδιωτικό solution scaffold και ξεχωριστό έλεγχο του starter structure.
- Εκτέλεση στην πραγματική πλατφόρμα (Colab/Windows) δηλώνεται `PASS` μόνο αν πραγματοποιήθηκε. Διαφορετικά `NOT TESTED`.

## 9. Πρακτικό rubric αξιολόγησης

| Κριτήριο | Τι πρέπει να επιβεβαιωθεί |
|---|---|
| Μαθησιακή αυτοτέλεια | ο αρχάριος καταλαβαίνει σκοπό, είσοδο, βήματα, αποτέλεσμα |
| Σωστή δομή | Markdown οδηγεί τη ροή· κώδικας εφαρμόζει το βήμα |
| Χρήσιμα σχόλια | εξηγούν νέα/κρίσιμα σημεία, χωρίς υπερσχολιασμό |
| Σωστά TODOs | δεν αποκαλύπτουν λύσεις, είναι επιλύσιμα από διδαγμένα στοιχεία |
| Επαλήθευση | προσδοκώμενο αποτέλεσμα και ποιοτικοί/αριθμητικοί έλεγχοι |
| Αναπαραγωγιμότητα | dataset, CRS, paths, runtime, σειρά εκτέλεσης |
| Ακεραιότητα | καμία απώλεια παλιού υλικού ή αλλαγή εγκεκριμένων δεδομένων |
| Τεχνική συμμόρφωση | nbformat, 0 outputs/counts, static QA, private runtime QA |
